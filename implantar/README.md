# Dossiê de Implantação Frontend 10/10 — Gestão Academia

> **Leitura obrigatória do executor:** este diretório substitui qualquer instrução anterior fragmentada.
>
> O executor **não decide arquitetura**, **não inventa fluxo**, **não omite tela**, **não pula validação**. Ele apenas executa exatamente o que está definido aqui.

## Regra de execução

1. Ler nesta ordem:
   - `implantar/00-escopo-do-projeto.md`
   - `implantar/01-diagnostico-real.md`
   - `implantar/02-estado-alvo-10-10.md`
   - `implantar/03-arquitetura-monorepo-e-pastas.md`
   - `implantar/04-contratos-api-e-modelos.md`
   - `implantar/05-rotas-formularios-e-fluxos.md`
   - `implantar/06-plano-sequencial-de-execucao.md`
   - `implantar/07-snippets-e-padroes-obrigatorios.md`
   - `implantar/08-checklist-final-e-push.md`

2. Executar **sem abrir novas frentes fora da ordem**.
3. Corrigir o frontend **de uma vez**, evitando retrabalho.
4. Pensar no projeto já pronto para entrar em **monorepo**.
5. Ao final:
   - remover arquivos de instrução temporária em `implantar/`
   - manter apenas `implantar/99-resumo-execucao.md`
   - fazer commit e push na `main`

## Regras absolutas

- Manter a identidade visual atual como base, elevando para **10/10**.
- Toda página deve conter o rodapé com o texto **"Desenvolvido por MtsFerreira"** e link para `https://MtsFerreira.dev`.
- Remover qualquer menção a plataformas de geração de código, IA, assistentes ou ferramentas similares do repositório.
- Limpar arquivos, estados e informações desnecessárias.
- Conectar cada informação às telas a que ela pertence.
- Preparar o frontend para backend real, com contratos e adapters claros.
- Não deixar formulário incompleto.
- Não deixar rota sem propósito.
- Não deixar estado duplicado sem necessidade.

## Entrega esperada do executor

Entrega única, consistente e validada, com:
- frontend funcional
- fluxos completos
- formulários completos
- rotas completas
- estrutura limpa
- documentação final resumida
- push realizado
